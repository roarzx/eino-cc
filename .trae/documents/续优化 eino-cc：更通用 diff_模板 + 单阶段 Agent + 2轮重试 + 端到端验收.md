## 目标与验收
- **目标**：把当前 MVP 的 Agent 修复闭环稳定下来，并在真实仓库完成一次“搜索→读取→生成补丁→应用→测试→输出 diff”的端到端跑通。
- **验收**：
  - CLI 输入一句目标文本后，日志能看到 Search/Read/Patch/Apply/Test。
  - 最多 2 轮（1 次重试）内：测试通过则输出 git diff；失败则输出明确失败原因与最后一次测试输出。
  - 在一个真实 Git 仓库上复现并跑通一次闭环。

## 单阶段 Eino Agent（保留当前架构，收敛循环）
- **单阶段**：保持一个 Agent（无 Planner/Reflect/V2 状态机），但把“每轮”定义为：一次完整工具序列 + 运行测试。
- **2 轮限制**：把 `max_iterations` 的语义对齐到“修复尝试次数=2”，并确保 Runner 的循环严格只跑 2 次（首次 + 一次重试）。
- **失败回灌**：第 2 轮把第 1 轮的测试 stdout/stderr 作为明确输入追加到 goal 中，指导模型更聚焦。

## Prompt 约束 + Patch 生成（让模型更稳定地产出可应用 diff）
- **更强约束**：
  - 明确要求：必须 `search_code`→`open_file(实现)`→输出 `diff --git`→`apply_patch`→`run_cmd(test)`。
  - 明确禁止：读到实现文件后重复 repo_tree/search_code；避免模型“兜圈子”。
- **Patch 模板**：在 prompt 中提供最小可行 diff 样例（包含 `diff --git` / `---` / `+++` / `@@` / `+/-`）。
- **Patch 内容范围**：要求补丁只覆盖目标仓库文件；不允许把工具实现（eino-cc 自己）混进补丁。

## 更通用的 diff 解析与应用策略（让 apply_patch 更鲁棒）
- **归一化**：兼容模型输出中的：代码块包裹、JSON/转义字符串、混合文本。
- **多段 diff 分块**：按 `diff --git` 切块后，只保留“命中 repo_root 下真实存在路径”的块。
- **严格校验**：拒绝没有 `diff --git` 的补丁；对明显不完整/损坏的 diff 给出可诊断错误。
- **回退策略（可选）**：当 git apply 因格式损坏失败时，针对“单文件少量行替换”的补丁尝试安全回退应用（仅在能明确定位 old/new 行时启用）。

## 自动修复模板（从“特例”变成“可控的通用兜底”）
- **兜底触发条件**：仅当模型未给出可解析 diff 或多次输出无补丁时触发。
- **模板集合（小而有效）**：
  - Go：算术返回值、比较符/边界条件、错误处理返回值、常见 off-by-one。
  - 测试驱动：从测试断言提取 expected/got，回推最小修复点（只改实现，不改测试，除非用户要求）。
- **安全边界**：兜底只允许修改被 `open_file` 读到且命中失败栈/搜索结果的文件。

## 端到端验收流程（真实仓库跑通）
- **验收仓库选择**：用你指定的真实 Git 仓库（或继续用 `test-repo` 作为冒烟）。
- **验收用例**：
  - 1 个“明确函数修复 + go test”用例。
  - 1 个“搜索定位 + 改动 + 测试”用例（确保 search_code/open_file 真在用）。
- **输出检查**：确认最终输出包含：测试结果（通过/失败原因）+ `git diff`。

## 交付物（代码改动范围）
- Runner：收敛为严格 2 轮、失败回灌、输出结构稳定。
- Prompt：补丁模板 + 更强约束。
- ApplyPatch：diff 归一化/分块过滤/校验/可选回退。
- 工具层：记录 open_file 的“净内容/路径”，便于兜底模板与安全边界。
